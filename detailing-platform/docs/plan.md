# План работ: восемь этапов

Разбивка выведена из двенадцати архитектурных инвариантов и требований доски
MVP. Явного списка «этапы 1–8» в доске нет, поэтому порядок задан здесь и
дальше считается рабочим.

Принцип: каждый этап заканчивается проверкой, которую можно запустить одной
командой. Этап без проходящей проверки не считается закрытым.

---

## Этап 1. Каркас и правила — **закрыт**

Репозиторий, `AGENTS.md`, `.env.example`, разделение секретов по месту
исполнения, `package.json` со скриптами конвейера.

Проверка: `node scripts/pipeline/tenant-new.mjs --help` отрабатывает без
установки зависимостей.

## Этап 2. Схема данных — **закрыт**

Тенанты, членство владельцев, каталог услуг и постов, расписание с
исключениями. Составные внешние ключи `(tenant_id, id)`.

Проверка: `npm run db:reset` — 12 миграций накатываются на чистую базу.

## Этап 3. Занятость и атомарные операции — **закрыт**

Единая `resource_occupancies` с `EXCLUDE USING gist`. Создание, перенос,
отмена и блокировка поста одной транзакцией. Идемпотентность по ключу.

Проверка: `npm run db:test` (15 инвариантов) и `npm run db:test:concurrency`
(24 параллельных клиента, проходит ровно один).

## Этап 4. Доступ и права — **закрыт**

RLS на всех таблицах, точечные `GRANT` по колонкам, токен доступа клиента,
подтверждение членства владельца на сервере.

Проверка: `npm run db:test` — файл `02_security.sql`, 17 проверок под
`set role anon` и `set role authenticated`.

## Этап 5. Свободное время, статистика, очередь — **закрыт**

`find_free_slots` как единственный расчёт для формы и помощника.
Статистика с разделением заездов, выполненных работ и полученных денег.
Очередь уведомлений с арендой и дедупликацией. Атомарные счётчики лимитов.

Проверка: `npm run db:test` — файл `03_free_slots.sql`, 7 проверок.

## Этап 6. Конвейер студий — **закрыт**

`tenant:new`, `tenant:validate`, `tenant:publish`, `tenant:verify` на чистом
Node. Детерминированные идентификаторы, сохранность броней и фото владельца
при переиздании.

Проверка: полный прогон на двух студиях, включая переиздание с изменённым
конфигом и сверку числа броней до и после.

## Этап 7. Серверные функции — **частично**

Написано: `booking` (создание, перенос, отмена, чтение по токену),
`assistant` (ограниченный цикл инструментов, запасной разбор без модели,
разделение полномочий), каталог инструментов, вывод токена через HMAC.

Проверено: **только роутер** — 21 тест встроенным раннером Node.
Не проверено: HTTP-слой, обращение к модели, вызовы RPC через supabase-js.
Блокер: нет Deno и нет проекта Supabase.

## Этап 8. Приложение — **не начат**

React 19, TypeScript strict, Vite, React Router, TanStack Query, Zod,
shadcn/ui + Astryx, PWA с манифестом на каждую студию.

Блокер: npm закрыт (403). Подключить Astryx его командами и прочитать
документацию установленной версии невозможно, а придумывать props компонентов
запрещено правилами проекта.

---

## Порядок снятия блокеров

1. Открыть npm → закрывается этап 8 и проверяется этап 7 локально.
2. Завести проект Supabase → Edge Functions, Auth, Storage.
3. Выдать ключ модели → помощник переходит из режима разбора по правилам
   в полноценный.
